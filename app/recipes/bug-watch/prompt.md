# 任务

从提交与 diff 中识别：

1. **缺陷修复**：fix/closes/resolves 类提交、防御性修补（空指针/边界/竞态/异常吞噬）
2. **破坏性变更**：API 签名变化、配置格式变化、行为变化、删除功能——这些对该仓库的使用方最重要
3. 每条给出：commit 短 sha 信源 + 一句话影响评估（谁会受影响）

# 输出契约（违反即作废重来）

1. 输出完整 bugwatch.md（新条目在「## {{DATE}}」小节下）：

```
<<<FILE:bugwatch.md>>>
（完整 markdown）
```

2. **仅当**发现破坏性变更时输出警报行（没有就不输出）：

```
<<<ALERT:breaking|破坏性变更标题|一句话影响与信源sha>>>
```

3. 最后一行摘要：

```
<<<META:summary>>>一句话：本批修复了什么/有无破坏性变更（≤60字）
```

- 没有缺陷修复也要输出文件（写「本批无缺陷修复类提交」）；不得编造 sha
